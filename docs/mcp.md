# Local MCP adapter

Install the optional MCP v2 SDK and start the local stdio server using a private device alias configuration.

```bash
python -m pip install 'moyu-harmony-pilot[mcp]'
harmony-pilot-mcp --config devices.local.json --allow-action device.health
```

The equivalent module entry point is `python -m moyu_harmony_pilot.mcp`. The core CLI remains usable with its standard-library runtime dependencies.

## Safe mode

Default tools are `devices`, `health`, `dump_ui`, `screenshot`, `list_actions` and `run_action`. Action execution requires explicit repeated `--allow-action ACTION_ID` arguments at startup. The empty default allowlist exposes observations. Local-only plugins are rejected by the shared registry.

Device selection accepts configured aliases. Screenshots are generated in the private diagnostics directory and returned as local file metadata. `som=true` uses the optional `[vision]` renderer and returns matching compact references. Screenshot filenames are generated by the adapter.

Tool responses include `ok`, `data` and structured errors. The MCP `isError` flag also marks unsuccessful calls. Plugin progress goes to stderr. Mutations reuse the same `ActionRunner`, locks, thermal guard and SQLite ledger as the CLI and Bridge.

## Local lab mode

```bash
harmony-pilot-mcp --config devices.local.json --local-lab --max-steps 20 --timeout 60
```

Lab mode adds `lab_observe`, `click_ref`, `swipe` and `back`. The first interactive call for an alias starts its fixed session deadline. Each alias retains that session budget for the lifetime of the server. Tool calls cannot renew it.

Use `lab_observe` to obtain a current `layout_hash`. Pass that hash with each step. The shared `InteractionSession` refreshes references, checks sensitive screens and temperature, applies the action, and returns the new snapshot with layout, foreground and focus feedback. A post-input uncertainty requires observation before another step.

The server uses stdio and executes callbacks on the main thread so the existing POSIX action budget remains active. It serializes local calls. Use independent processes for separate long-running device workloads, sharing the configured state directory where physical devices overlap.

## Client configuration

Configure an MCP client to launch the executable with explicit absolute paths. A typical client configuration follows. Adapt the outer configuration shape to the client.

```json
{
  "mcpServers": {
    "harmony-pilot": {
      "command": "/ABSOLUTE/PATH/.venv/bin/harmony-pilot-mcp",
      "args": [
        "--config", "/ABSOLUTE/PATH/devices.local.json",
        "--state-dir", "/ABSOLUTE/PATH/.state",
        "--allow-action", "device.health"
      ]
    }
  }
}
```

The standard Agent Skill is available at `skills/harmony-pilot/SKILL.md`. Copy that directory into the skill location used by the chosen agent.
